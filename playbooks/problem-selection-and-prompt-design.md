# Problem selection and prompt-design playbook

Use this playbook when a researcher wants to use the archive's accumulated evidence to select a promising problem for AI reasoning or agentic workflows, then design a fresh, domain-specific prompt. It is a reusable reference asset, not a record of that researcher's run.

Run the resulting study in a separate local workspace by default. The archive does not aim to collect every screening ledger, experiment script, or personal research output. If a run becomes a shareable documented attempt, submit it through the [contribution workflow](../SUBMISSION_WORKFLOW.md).

## Prompt to run

```text
Use the Prompts for Progress repository at its current checked-out commit as evidence for a local problem-selection and research-prompt design study.

Mode: [SCREEN THE ARCHIVE FOR A PROBLEM / DESIGN FOR THE PRESELECTED PROBLEM: name].

This is a local research-planning exercise. Do not create a project directory, commit, or add files to the Prompts for Progress repository unless separately asked. Preserve any unrelated local work. Record the repository commit, date, and sources consulted in the local study notes.

First consult the latest prompt-methods synthesis if it is relevant and within its rights boundary. Do not create a new whole-corpus methodology review merely to design one prompt. If the latest synthesis is unavailable, stale, or too general, prepare a compact evidence brief using only the cases and methods relevant to this problem's domain and verification model.

If screening is requested, assess each candidate against explicit criteria:

- a clear, stable, self-contained statement;
- a realistically verifiable success result, preferably with an independently checkable certificate, test, or proof obligation;
- no need for new data assets, a mutable live service, a laboratory, proprietary tooling, or specialized infrastructure;
- a plausible leverage point for reasoning or an agentic workflow rather than unbounded brute-force computation;
- a meaningful attempt relative to documented prior work; and
- an honest status and novelty boundary, including any need for current literature or expert review.

Maintain a local candidate ledger, including exclusions and uncertainty. If the problem is preselected, skip broad screening and focus on the relevant evidence brief.

For every chosen problem, prepare a dossier containing: the self-contained statement; baseline and provenance; why it was selected; transferable methods from the archive; required durable artifacts; exact success, non-success, and claim boundaries; verification plan; resource envelope; and stopping rules.

Then write the complete prompt for a fresh research task. It must favor reasoning, explicit hypotheses, and falsification over unbounded computation. Require a route or artifact ledger; use positive and negative controls where appropriate; distinguish same-model critique from independent verification; preserve a valid incumbent when search is involved; and require an honest, useful handoff if unresolved. Do not claim current novelty, a record, or a final theorem without an appropriate dated prior-art check or expert review.

Finish with the selected problem (or screened candidates), evidence for viability, the full custom prompt, exact validation planned or performed, and unresolved risks. If the later run is suitable for public contribution, use the repository's issue-based submission workflow rather than depositing all local working assets directly into the archive.
```

## Contribution boundary

The output of this playbook normally remains with the researcher. A proposed archive contribution should be a documented attempt with the prompt, durable artifacts, validation evidence, provenance, and an honest outcome—not an unreviewed bundle of private working files.
